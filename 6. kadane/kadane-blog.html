Kadane’s Pattern: The Subarray That Taught Us to Forget

We have spent the last few articles learning to think in terms of constraints. We didn’t begin with patterns. We began with a problem. The problem gave us a constraint, the constraint made some approaches painful, the pain gave us an idea, and the idea eventually became a pattern.

Sliding Window followed exactly this path. We noticed that instead of rebuilding contiguous ranges, we could move a window and reuse what we already knew. Now we look at another family of contiguous-subarray problems, but the question changes. It is no longer how do we move the window? It is what should we do with the past? Sometimes the past helps us. Sometimes it hurts us.

1. A new problem, and the obvious way to solve it

Consider the array [-2, 1, -3, 4, -1, 2, 1, -5, 4]. We want a contiguous subarray with the largest possible sum. For example [4, -1, 2, 1] has sum 4 + (-1) + 2 + 1 = 6, and 6 is the maximum. This is the famous Maximum Subarray problem. But let’s pretend we have never heard of Kadane’s algorithm.

The naive way

A subarray is defined by two boundaries, a start and an end. So try every start, and for each start try every end: [-2], [-2, 1], [-2, 1, -3], and so on, then move the start and repeat. For an array of length n there are roughly n² subarrays. That is already uncomfortable.

Drag the slider to feel it.

Can we at least make each sum cheap?

If we already know sum([4, -1, 2]) = 5, there is no reason to recompute the whole thing for [4, -1, 2, 1]. We just add the new element: 5 + 1 = 6. This is the sliding-window instinct again: don’t throw away work that can be reused. So we scan with a running sum. But that raises a new question.

2. What are we maintaining?

Walk through the array extending one subarray forever. The running sum goes -2, then -1, then -4, then 0 when we reach 4.

Something feels wrong. We have reached a 4, but our history [-2, 1, -3] (sum -4) is dragging us down. Attach the 4 to it and we get 0. Forget everything and take just [4], and we get 4. That is much better, and it leads to the important question.

3. Should we carry the past forward?

At every element x we have exactly two choices.

  • Extend the existing subarray: previous_sum + x
  • Restart at this element: x

So the decision is max(previous_sum + x, x). That is the heart of Kadane’s idea, but there is a deeper reason it works.

When does the past become harmful?

Suppose the previous sum is -4 and the next number is 7. Carrying the past gives 3; forgetting it gives 7. The history actively made things worse. And it doesn’t matter what created the -4. It could be [-2, -2], or [10, -20, 6], or [-100, 96]. Once the best sum we can carry forward is negative, the details are irrelevant. This is our first major compression of information. Try it:

A negative-sum subarray can never improve the sum of a future subarray. If we must choose between carrying a negative sum forward and starting fresh, starting fresh is always at least as good.

At every element, Kadane’s asks one question: is my history helping me or hurting me?

We have accidentally discovered the algorithm

Python code (click to hide or show)
def max_subarray(nums):
    current = nums[0]
    best = nums[0]

    for x in nums[1:]:
        current = max(x, current + x)
        best = max(best, current)

    return best

The code is almost the least interesting part. The interesting part is why the two variables exist.

5. Why two values?

current answers: what is the best sum of a subarray that must end here? best answers: what is the best sum we have seen anywhere so far? These are different questions. Take [4, -1, 2, 1, -10]. After the first four elements both are 6. Then -10 arrives and current becomes -4, since the best subarray ending here is the whole array. Have we forgotten that 6 was achievable? No. That is what best remembers.

Forgetting is not erasing

When we restart, we are not saying “everything before this was useless.” Maybe it was the best subarray we have seen. We are saying something more precise: everything before this is no longer useful for extending a subarray into the future. There are two kinds of memory, and current and best hold one each.

Why does contiguity matter so much?

If elements could be picked freely, we would just take all the positives. We can’t. Once we continue a subarray we must take the next element. So every new element creates a binary decision, extend or restart, and because we only care about the best subarray ending here, all worse histories can be discarded.

6. What if every number is negative?

This is where careless implementations go wrong. For [-8, -3, -6, -2, -5] the answer is [-2] with sum -2. If we initialize current = 0 and best = 0, we return 0, which is not the sum of any non-empty subarray.

So we initialize from the first element. “Restart” means start a real subarray at this element, not “choose nothing.” This also gives the recurrence a clean meaning from the very first step.

7. The same idea as dynamic programming

Another mental model: every subarray carries a score, and if it falls to -7 you would rather open a new account than carry that debt. Formally, define dp[i] as the maximum sum of a subarray ending at index i. Then dp[i] = max(nums[i], dp[i-1] + nums[i]) and the answer is max(dp[i]).

We never said “let’s use DP.” We asked what information about the past actually matters, and the answer was the best subarray ending at the previous position. Then we noticed that dp[i] only depends on dp[i-1], so why store the whole table?

The brute force wasn’t wasted either. Two subarrays ending at the same index with sums -5 and -2 are interchangeable from the future’s point of view, except that -2 is better, so we keep only the best one.

Why not the simpler approach?

Try every subarrayDP arrayKadane’s
TimeO(n²) with a running sumO(n)O(n)
Extra spaceO(1)O(n)O(1)
ReasoningEasy to trust, slowMakes the state explicitKeeps only the state the next decision needs

The DP array isn’t wrong. It is the best way to discover the state, and writing it first is a perfectly good habit. The lesson is: first discover the state, then ask how much of it you actually need to keep.

9. The bigger pattern

It is tempting to write “Kadane’s = maximum subarray sum.” That is too shallow. The deeper pattern is to maintain the best useful state ending at the current position, and decide whether extending it beats starting fresh. Negative history is discarded, useful history is carried, and independently the global best is tracked because the winner may have ended earlier.

When a problem seems to demand remembering a huge number of possibilities, don’t immediately ask what data structure stores them all. Ask whether you really need all of them. Maybe many histories are indistinguishable from the future’s perspective. Maybe only the best one matters. Sometimes that realization is the entire algorithm.

What is the smallest piece of information from the past that is sufficient for the next decision?

10. A useful way to recognize these problems

  1. Is the answer contiguous? A subarray or substring that must be one unbroken piece.
  2. Does every element force a choice? Continue what we have, or begin again here.
  3. Can a bad history be recognized without knowing its details? If one number summarizes how harmful it is, we can discard it.
  4. Can the best answer end earlier than the current position? If so, keep a separate best.

11. The evolution of the idea

These next problems aren’t unrelated tricks. They are the same idea under a changing constraint.

ProblemWhat it teaches
Maximum sumOne state: the best sum ending here. Forget negative history.
Minimum sumThe mirror image. The reasoning should feel familiar.
Maximum productA negative result can suddenly become extremely valuable, so we may need to track the minimum too.
Delete one elementOne state is no longer enough; we need to track whether the deletion has been used.
Circular arrayThe best subarray may wrap around the end.
Repeated arrayDo we really need to build the repeated array?

Every time, the loop is the same: constraint, what information matters, what can be forgotten, what state survives, what decision we can make.

The most important thing to remember is not the formula current = max(x, current + x), but the question that produced it. Sometimes the smartest thing an algorithm can do with the past is let it go.

Kadane’s Pattern: When the Problem Changes the State

In the first article we discovered Kadane’s algorithm from one question: is the history I’m carrying helping me or hurting me? In the second we saw that the rule wasn’t universal. For products, negative × negative = positive, so we could no longer throw negative states away and had to keep both current_max and current_min. The state we maintain is determined by what the future might need.

Now we introduce another kind of change. We won’t change the operation or the objective. We’ll change the rules of the problem, and that will force the state to evolve again.

Ask what the future needs to know. Sometimes the answer is more state, and sometimes it is a different way of looking at the problem.

1. One small change: delete one element

Start with the familiar problem, the maximum sum of a contiguous subarray, and add one permission: you may delete at most one element. Take [1, -5, 4]. Without deletion the best is [4] = 4. With deletion we can take [1, -5, 4], delete -5, and get [1, 4] = 5.

The naive way

Try every subarray and, for each, try deleting every element, which is cubic work. We want to reuse the Kadane idea instead, so we ask what our old state remembers.

Why our old state is not enough

Standing at the 4, there are two histories. History A deleted nothing: [1, -5, 4] sums to 0. History B already deleted the -5: [1, 4] sums to 5. If another bad element arrives, as in [1, -5, 4, -10], B has already spent its deletion and A hasn’t. Two histories that looked equivalent before are no longer equivalent.

The constraint creates the state. We didn’t add a second state because it sounded clever. The problem demanded it.

So we track two things: no_delete, the best subarray ending here without using a deletion, and deleted, the best subarray ending here after using one.

2. Deriving the two states

no_delete is ordinary Kadane’s: new_no_delete = max(x, no_delete + x).

For deleted, ask how we could possibly arrive at this state. There are two ways. We already deleted something earlier and just extend it (deleted + x), or we delete the current element, skipping x and reusing the previous no_delete. So new_deleted = max(deleted + x, no_delete). Listing every way to reach a state is a very general way to derive DP transitions.

no_delete --keep x-----> no_delete
no_delete --delete x---> deleted
deleted   --keep x-----> deleted
deleted   --> no_delete  (impossible: a deletion can’t be undone)

Watch the state machine

Step through, and pay attention to the -5, where no_delete hands its value over to deleted. We start with deleted = −∞, because no valid subarray with a deletion exists yet, and we must not confuse “nothing deleted” with “one deleted.”

Yellow is the current element and green the elements seen so far. The table records each step. Every cell is simply the best of the valid ways to reach that state.

3. Precise state meanings and the code

no_delete does not mean “I have never seen a negative number.” It means the best valid subarray ending here where I have not used my deletion. deleted doesn’t mean “I deleted the current element.” It means the best valid subarray ending here where my one deletion has already been used. If you can’t say exactly what a DP variable means, the recurrence is hard to derive and harder to trust.

This also explains why the second term is just no_delete[i-1] and not no_delete[i-1] + nums[i]: in that transition we’re deleting nums[i], so we skip it.

And the first element? For [-1] the standard problem requires the subarray to be non-empty after the deletion, so the answer is -1, not 0. State definitions must match the problem’s exact rules.

The complete algorithm

Python code (click to hide or show)
def max_subarray_one_deletion(nums):
    no_delete = nums[0]
    deleted = float("-inf")
    best = nums[0]

    for x in nums[1:]:
        new_no_delete = max(x, no_delete + x)
        new_deleted = max(deleted + x, no_delete)

        no_delete = new_no_delete
        deleted = new_deleted

        best = max(best, no_delete, deleted)

    return best

As in ordinary Kadane’s, each state depends only on the previous layer, so we keep two numbers instead of a table. And we compute both new values before overwriting either: if we updated no_delete first, the deleted line would see the new no_delete when it needs the old one.

Why not the simpler approach?

One stateTwo states
TimeO(n)O(n)
Extra spaceO(1)O(1)
ReasoningCan’t tell whether the deletion is spentRemembers the history of the action

Again the cost is trivial. The question was never speed, only whether the state keeps what the future needs.

Whenever a problem introduces an action that changes what you may do later, ask whether your state needs to remember if that action has already happened.

4. Two deletions? K deletions?

Don’t solve it, just think about the state. With one deletion we had 0 or 1 deletions used. With two we’d have dp0, dp1, dp2, each meaning the best sum ending here with that many deletions used. For “at most K,” the state becomes dp[k]. The constraint asks “how much special power have I used?” and the state remembers exactly that. Drag the slider.

5. Circular arrays: transform instead of expand

Now make the array circular. In [5, -3, 5] a subarray may wrap around, so [5, 5] is allowed because the ends are adjacent. Our assumption that a subarray is one segment of a linear array has broken. Do we need a completely new algorithm?

The naive way

Consider every starting point and every length around the circle, again quadratic work.

Find what we don’t want

A circular subarray either doesn’t wrap (an ordinary subarray, which we know how to find) or wraps, looking like suffix + prefix. For [5, -3, 5] we take [5] + [5] and exclude [-3]. The excluded part is one contiguous middle section, so

wrapping sum = total sum − minimum subarray sum

To get the largest wrapping subarray, remove the smallest middle section. We already derived the minimum subarray in article 2, so the answer is max(maximum_subarray, total − minimum_subarray). Step through three arrays, including the trap.

Green elements are kept, grey are excluded, and blue marks the best non-wrapping subarray.

But there is a trap

For [-3, -2, -5], total is -10 and the minimum subarray is the entire array, -10, so total − minimum = 0. But 0 isn’t the sum of any non-empty subarray, since the “excluded” part was everything and we selected nothing. So if every element is negative, the answer is just the maximum element. A transformation can introduce solutions that are invalid for the original problem, so check that the transformed answer still represents a real one.

Python code (click to hide or show)
def max_circular(nums):
    cur_max = cur_min = best_max = best_min = nums[0]

    for x in nums[1:]:
        cur_max = max(x, cur_max + x)
        cur_min = min(x, cur_min + x)
        best_max = max(best_max, cur_max)
        best_min = min(best_min, cur_min)

    if best_max < 0:
        return best_max

    return max(best_max, sum(nums) - best_min)

Compare this with deletion. There the constraint forced us to add states. Here we didn’t need more state; we transformed the problem. The skill is knowing which one is appropriate.

6. K-concatenation: summarize instead of build

Take A = [1, -2, 3] repeated k times. If k is enormous, building the array is wasteful, and we don’t need to. A maximum subarray can stay inside one copy, cross one boundary, or, if the total sum is positive, benefit from spanning many copies. So we only need four numbers about one copy: maximum subarray sum, maximum prefix sum, maximum suffix sum, total sum. Drag k and compare the answer from the real built array with the one from the four-number summary.

Python code (click to hide or show)
def k_concat_max(arr, k):
    kad = cur = arr[0]
    for x in arr[1:]:
        cur = max(x, cur + x)
        kad = max(kad, cur)
    if k == 1:
        return kad

    total = sum(arr)
    pre = max(sum(arr[:i + 1]) for i in range(len(arr)))
    suf = max(sum(arr[i:]) for i in range(len(arr)))

    ans = max(kad, suf + pre)
    if total > 0:
        ans = max(ans, suf + (k - 2) * total + pre)
    return ans

Don’t represent the entire future if a compact summary of the past is enough to reason about it.

7. What these problems taught us

A state is a compressed past: all possible histories collapse into the smallest set of numbers that preserves what the future could need. Click through the journey.

8. The bigger pattern

The deeper pattern isn’t current = max(x, current + x), which is merely the simplest instance. It is to walk through a sequence while maintaining the smallest amount of information that describes every relevant way the past can affect the future. Sometimes that is one number, sometimes two, sometimes a handful of states, and sometimes the right move is to transform the problem.

When the problem changes, don’t ask “what is the new formula?” Ask “what changed about the future?” and then “what information do I now need to preserve?”

9. A useful way to recognize these problems

  1. What decisions have already happened? Deleting an element, using a skip, flipping a sign.
  2. Which of those affect what I’m allowed to do next? Those are candidates for state.
  3. Which different histories lead to different futures? Those become separate states.
  4. Which histories are indistinguishable from here onward? Merge them. That is where the compression happens.
  5. Is the structure itself the issue? If the array is circular or repeated, consider a complement or a summary instead of more state.

Next we ask what happens when we may change the structure of the subarray itself: modify part of the array, splice one array into another, or optimize something other than the plain sum. Kadane’s starts connecting with state machines, prefix/suffix reasoning and complementary transformations.

The formula was never the destination. The destination was learning to ask what information from the past is still relevant to the future, so that the state isn’t something you memorize. You derive it.

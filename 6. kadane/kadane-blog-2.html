Kadane’s Pattern: When One State Is Not Enough

In the previous article we arrived at Kadane’s algorithm almost by accident. We asked for the maximum sum of a contiguous subarray, noticed that a running sum only matters if it is helping us, and derived current = max(x, current + x) plus a separate best. It was a remarkably small amount of state for a problem with a huge number of subarrays.

Now we make things more interesting, because a deeper question was hiding underneath: what if the information we are keeping is no longer enough?

A state that looks useless now may be essential later.

1. Turning Kadane’s upside down

Suppose we ask for the minimum sum of a contiguous subarray instead. This sounds like a new problem, but let’s resist learning another algorithm and go back to the reasoning. For the maximum, a positive history helps and a negative one hurts, so positive is kept and negative is discarded. For the minimum, a negative history helps and a positive one hurts. The reasoning flips. The problem didn’t change; we only changed what “useful” means.

The naive way

Try every subarray again, n² of them. We already know that is wasteful.

Same question, opposite direction

Take [3, -4, 2, -5, 1]. Carrying 3 and meeting -4: continue gives -1, restart gives -4, and for a minimum -4 is better, so restart. Carrying -4 and meeting 2: continue gives -2, restart gives 2, so continue. Flip the mode and watch the same array get two different answers.

Yellow is the current element, green is the subarray being carried, grey is forgotten history.

The recurrence comes from the meaning of the state. We didn’t memorize “maximum → max, minimum → min.” We reasoned about what kind of past helps the objective.

DiscardNegative historyPositive history

The complete algorithm

Python code (click to hide or show)
def min_subarray(nums):
    current = nums[0]
    best = nums[0]

    for x in nums[1:]:
        current = min(x, current + x)
        best = min(best, current)

    return best

2. Maximum absolute sum: composing old ideas

Now ask for the largest |sum| over all subarrays, for example in [1, -3, 2, 3, -4]. Since |x| = max(x, -x), there are only two possibilities: the largest positive subarray sum, or the most negative one with its sign flipped.

The naive way

Try every subarray, take absolute values, keep the largest. Again n².

Two sides of the same problem

We already have both algorithms, so

maximum absolute sum = max(maximum subarray sum, −minimum subarray sum)

Here the maximum is [2, 3] = 5, the minimum is [-4] = -4, so the answer is max(5, 4) = 5. Step through both scans running side by side.

Green is the best maximum subarray, blue is the best minimum subarray, yellow is where they overlap.

Python code (click to hide or show)
def max_abs_sum(nums):
    cur_max = cur_min = best_max = best_min = nums[0]

    for x in nums[1:]:
        cur_max = max(x, cur_max + x)
        cur_min = min(x, cur_min + x)
        best_max = max(best_max, cur_max)
        best_min = min(best_min, cur_min)

    return max(best_max, -best_min)

As understanding grows, new problems often become compositions of old ideas rather than completely new tricks. This is a nice example of state reuse.

3. Maximum product: one state is no longer enough

So far the rule has been to keep the state that is useful for the objective. Now change the operation. Instead of adding elements, multiply them, and our intuition starts to break.

Find the contiguous subarray with the largest product in [-2, 3, -4].

The naive way

Try every subarray and multiply. And the tempting shortcut is to keep only the maximum product ending here: -2, then -2 × 3 = -6, then -6 × -4 = 24. Something strange happened. The state that looked terrible in the middle, -6, became extremely valuable. Our old rule, “if the state is bad, throw it away,” is no longer safe, because negative × negative = positive.

Don’t throw this state away

With addition, a negative sum is always harmful when maximizing. With multiplication, a negative product might be exactly what we need. Step through the centerpiece example.

Try it with any next number. The state is max = 3, min = -6. Drag the incoming x and watch which state wins.

If the future can turn a currently bad state into a good one, you cannot safely discard that state. We need current_max and current_min.

Deriving the recurrence

Rather than memorize it, list every way the new state can arise. With a new number x there are three: start a new subarray (x), extend the old maximum (current_max * x), or extend the old minimum (current_min * x). So new_max is the max of the three and new_min is the min of the three. Both must be computed from the old values, so the transition is simultaneous. Don’t overwrite current_max before computing new_min.

You drive it

At each step, which candidate gives the new maximum?

The complete algorithm

Python code (click to hide or show)
def max_product(nums):
    current_max = nums[0]
    current_min = nums[0]
    best = nums[0]

    for x in nums[1:]:
        new_max = max(x, current_max * x, current_min * x)
        new_min = min(x, current_max * x, current_min * x)

        current_max = new_max
        current_min = new_min

        best = max(best, current_max)

    return best

Zero gives us another clue

Any product containing zero is 0, so zero acts as a boundary. In [2, 3, -2, 0, 4] the products before and after the zero are separate worlds. Run the three presets below and watch both states collapse at the zero.

Some values naturally reset the state. For addition, a sufficiently harmful history may be discarded; for multiplication, zero wipes it out. The reason differs, but the instinct is the same: ask what information can still influence the future.

Why not the simpler approach?

Only current_maxBoth max and min
TimeO(n)O(n)
Extra spaceO(1)O(1)
ReasoningWrong on [-2, 3, -4] (gives 3, not 24)Keeps every state the future can use

The extra variable costs almost nothing, and the lesson isn’t that two is better than one. It is that the right number of states is decided by what the future can do with them.

4. State is a contract with the future

When we define current_max, we promise it holds everything the future needs about the best positive product ending here. current_min promises the same for the worst negative one. Together they summarize all relevant histories, and everything else can be forgotten.

An array with a million elements has millions of subarrays. We could remember all their products, but at each position we compress everything into three numbers: current_max, current_min, best. That is the central skill behind dynamic programming, and the question isn’t “which formula do I memorize?” but “what is the smallest state that makes the future independent of the forgotten past?”

6. The bigger pattern

We are no longer just learning Kadane’s. We are learning to design a state transition: the current element arrives, there are several kinds of state that can extend into it (a useful one, an alternate one), and together they feed the future decision.

For maximum sum we threw away negative histories, and that was safe. For maximum product it was not safe, because the operation changed. Addition preserves the ordering intuition, since negative + x is always worse than x when maximizing. Multiplication does not.

Never discard information merely because it looks bad right now. Discard it only when you can prove it can never become useful later.

7. A useful way to recognize these problems

  1. What is the objective? Maximum, minimum and absolute value all change which history is useful.
  2. Can the operation flip the meaning of a state? Multiplying by a negative does. If yes, keep both sides.
  3. Is the answer built from states I already have? Absolute sum was max and min combined.
  4. Are there reset values? Zero in a product splits the array into separate worlds.
  5. Can I prove the discarded state is never useful later? If not, preserve it.

8. The evolution of the idea

ProblemWhat it teaches
Maximum sumOne state: best sum ending here. Forget negative history.
Minimum sumInvert the objective and the useful history flips too.
Maximum absolute sumCombine two states you already have.
Maximum productChange the operation and one state becomes insufficient. Expand it.
Delete one elementChange what we are allowed to do. The state must remember whether the deletion is used.

So far we changed the objective. The next step is different: we change what we are allowed to do. Find the maximum subarray sum, but you may delete one element. Now the future needs to know whether we have already deleted one, so the state must grow again. That is where we go next.

A state that looks useless now may be essential later. Before discarding information, ask: can the future ever make this state useful again? If not, forget it. If yes, preserve it. And if the future must distinguish situations, the state must grow to represent them.

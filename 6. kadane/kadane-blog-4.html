Kadane’s Pattern: When Kadane Is Hiding Somewhere Else

So far Kadane’s has looked deceptively simple. We don’t need to remember every subarray, only the best useful history ending at the current position. Then sometimes one state wasn’t enough, sometimes the constraint changed the state, and sometimes the problem could be transformed into one Kadane already knew how to solve. This final article is about that last idea.

The goal is not to look at a problem and think “this is a Kadane problem.” It is to ask whether we can transform the problem until Kadane’s way of thinking becomes visible.

1. K-Concatenation Maximum Sum (LeetCode 1191)

Take nums = [1, -2, 1] and concatenate it 3 times: [1, -2, 1, 1, -2, 1, 1, -2, 1]. Find the maximum subarray sum. If k is small we can build the array and run Kadane’s. But what if k = 1,000,000,000? We still want a maximum subarray, but we can’t afford to construct the thing we’re supposed to search.

The naive way

Build the repeated array and scan it. That costs O(n·k) time and memory, which is hopeless for a billion copies.

What can one copy tell us?

Four things matter: the best subarray inside one copy (Kadane’s), the best prefix, the best suffix, and the total sum. Prefix and suffix matter because a subarray crossing the boundary between two copies is exactly best suffix of the left copy + best prefix of the right copy. The total matters because passing through a complete extra copy adds total to the sum. If the total is positive, more copies keep helping. If it is zero or negative, they don’t.

When the input is huge because of repetition, look for a compact summary of one repeated unit.

Pick an array, drag k, and compare the answer from the real built array with the one from the summary. The array grows, but the information needed to reason about it does not.

The complete algorithm

For k = 1 the answer is the best subarray. For k ≥ 2, run Kadane over two copies, which covers the boundary crossing, then add (k − 2) × total if the total is positive. LeetCode 1191 allows an empty subarray, so Kadane here starts from 0.

Python code (click to hide or show)
def k_concatenation_max_sum(nums, k):
    MOD = 10**9 + 7
    total = sum(nums)

    def kadane(arr):
        current = best = 0          # empty subarray is allowed
        for x in arr:
            current = max(0, current + x)
            best = max(best, current)
        return best

    if k == 1:
        return kadane(nums) % MOD

    best = kadane(nums * 2)
    if total > 0:
        best += (k - 2) * total

    return best % MOD

Why not the simpler approach?

Build the arrayTwo copies + total
TimeO(n·k)O(n)
Extra spaceO(n·k)O(n) for two copies
ReasoningObvious, impossible for huge kUses what one copy says about all of them

Building two copies is a convenience. We could also compute prefix and suffix directly and need only O(1) extra space. The lesson is the compression, not the implementation.

2. Maximum Score of a Spliced Array (LeetCode 2321)

Now a problem that doesn’t look like Maximum Subarray at all. We have nums1 and nums2, and we may choose one contiguous segment and replace it in nums1 with the matching segment from nums2. Maximize the sum. It sounds like array manipulation, so let’s slow down and ask what actually changes.

The naive way

Try every segment [l, r], swap it, and re-sum. That is cubic, or quadratic with prefix sums.

Look at each position independently

With nums1 = [1, 2, 3, 4] and nums2 = [2, 2, 5, 1], define gain[i] = nums2[i] − nums1[i], giving [1, 0, 2, -3]. If we splice a segment, the array gets better by exactly the sum of the gains inside it.

Replacement becomes gain, and the best splice is the maximum-sum contiguous subarray of the gain array. That is Kadane’s.

We didn’t recognize Kadane’s from the surface of the problem. We created a problem Kadane’s can solve. Choose a segment yourself and watch the score.

Now watch Kadane’s run over the gain array. The first preset borrows from nums2, the second borrows the other way.

Yellow is the current element, green the carried segment, grey forgotten history.

The other direction

We may also splice from nums1 into nums2, so we do the same thing with gain[i] = nums1[i] − nums2[i] and take the better result: max(sum(nums1) + best_gain_2_to_1, sum(nums2) + best_gain_1_to_2).

Python code (click to hide or show)
def maximum_spliced_array(nums1, nums2):
    def kadane_gain(a, b):
        current = best = a[0] - b[0]

        for x, y in zip(a[1:], b[1:]):
            gain = x - y
            current = max(gain, current + gain)
            best = max(best, current)

        return best

    sum1 = sum(nums1)
    sum2 = sum(nums2)

    gain_1_to_2 = kadane_gain(nums2, nums1)
    gain_2_to_1 = kadane_gain(nums1, nums2)

    return max(sum1 + gain_1_to_2,
               sum2 + gain_2_to_1)

This is pattern recognition at a deeper level: replacement → gain → maximum subarray → Kadane’s.

3. Substring With Largest Variance (LeetCode 2272)

This problem is harder because Kadane’s isn’t waiting for us. We have to uncover it. The variance of a substring is the largest difference between the counts of two characters in it, and we want the substring where that is greatest.

The naive way

Try every substring and count every pair of characters. Too slow, so let’s simplify by fixing one pair of characters, a (the major) and b (the minor), and ignoring every other letter.

Turn characters into numbers

Give a the value +1 and b the value -1. A substring’s sum is then count(a) − count(b). For "aababa" that is +1 +1 −1 +1 −1 +1 = 2. We want the contiguous region with the largest sum, which looks suspiciously like Maximum Subarray.

The catch

The substring must contain both characters. Plain Kadane’s on "aaaaa" would happily return 5, but there is no b. So the old state, current_sum, isn’t enough. We must also know whether a b is actually included. The state exists because the future needs information the old state didn’t preserve.

Resetting, carefully

When the running difference goes bad (count_b > count_a), normal Kadane’s says forget the past. We do, but with a twist. The reset happens right after reading a b, so that b is available as the first character of the next substring. A third state, can_extend, remembers that. Then a later run like "aaa" counts as 3 − 1 by borrowing that b. Step through it. The second preset, "baaa", is where the borrowing matters.

Green is the current candidate segment, grey is discarded. A candidate is valid only if it contains a b, or can borrow the one just before it.

Python code (click to hide or show)
def largest_variance(s):
    best = 0

    for major in set(s):
        for minor in set(s):
            if major == minor:
                continue

            major_count = 0
            minor_count = 0
            can_extend = False   # a minor sits just before this segment

            for ch in s:
                if ch == major:
                    major_count += 1
                elif ch == minor:
                    minor_count += 1

                if minor_count > 0:
                    best = max(best, major_count - minor_count)
                elif can_extend:
                    best = max(best, major_count - 1)

                if minor_count > major_count:
                    major_count = 0
                    minor_count = 0
                    can_extend = True

    return best

Why not the simpler approach?

Reset and forget everythingReset but keep can_extend
TimeO(26²·n)O(26²·n)
Extra spaceO(1)O(1)
ReasoningMisses "baaa": the useful b was thrown awayRemembers that the next segment can start with the b that caused the reset

A forgetful reset looks like it works on easy inputs and fails on inputs like "abaccc" (the answer is 2, from "accc"). It is the same lesson as the product problem: don’t discard information until you can show the future will never need it.

5. The bigger pattern

Kadane’s is not really about current = max(x, current + x). That is only the simplest expression of a deeper idea: maintain the smallest amount of information about the past that is sufficient to make the best decision about the future. Sometimes that is one number, sometimes two (max and min), sometimes a small state machine (no deletion, one deletion). Sometimes we don’t add state at all and transform the problem. And sometimes we transform it and then discover the transformed problem needs a modified state.

Kadane’s doesn’t live in a memorized recurrence. It lives in the state.

When a new contiguous-range problem appears, don’t ask “is this Kadane’s?” Ask what the problem is actually trying to optimize, then run it through this flow.

6. A useful way to recognize these problems

  1. What is this problem actually optimizing? Name the quantity, not the story.
  2. Can I express each element’s contribution more simply? Replacement became gain, letters became ±1.
  3. Does it reduce to the best contiguous accumulation? If so, Kadane’s is hiding there.
  4. What does the future need to know about the past? That decides the state.
  5. Did the transformation create invalid answers? “At least one b” and “non-empty” are the usual traps.
  6. Is the input huge because of repetition? Summarize one unit instead of building the whole.

7. The evolution of the idea, and what comes next

ProblemWhat it teaches
Maximum subarrayThe past either helps or hurts. If it hurts, throw it away.
Minimum subarraySame idea, opposite objective.
Maximum absolute sumOne direction isn’t enough. Combine max and min.
Maximum productA bad state can become good, so keep current_max and current_min.
One deletionThe future cares about an action already taken, so track it.
Circular subarrayTransform: wrapping sum = total − minimum subarray.
K-concatenationSummarize the repeated unit instead of constructing it.
Spliced arrayReplacement → gain → maximum subarray.
Largest varianceLetters → ±1, then an extra validity constraint forces extra state.

We have spent a lot of time on one question: how do I maintain the best contiguous segment while scanning? Now we approach contiguous ranges from a different direction. Instead of maintaining the best segment dynamically, can I preprocess the array so the sum of any range is available almost immediately? That question leads to our next pattern, Prefix Sum, and like Kadane’s it exists because a simpler approach eventually runs into a constraint.

The formula may change. The reasoning doesn’t.

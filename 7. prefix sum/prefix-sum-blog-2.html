When a Prefix Sum Becomes a Clue

A prefix sum started as a way to answer a range-sum query. Now we will use it to discover the range itself.

In the previous article we built prefix sums because repeatedly calculating overlapping ranges was wasteful. We learned that prefix = accumulated history and sum(left, right) = prefix[right + 1] − prefix[left]. That was already useful, but now we ask a slightly different question. 1. What if the range is unknown?

Take [1, 2, 3, 4, 5] and ask: does there exist a contiguous subarray whose sum is 6? This time nobody gives us left and right. We have to find them. Here [1, 2, 3] works, so the answer is yes.

The naive way

From every start, keep extending: [1], [1, 2], [1, 2, 3], and so on, then start again at 2. A running sum while extending avoids recalculating each subarray, which helps, but there are still roughly n² subarrays. So the real question is: can prefix sums help us discover the desired subarray without examining every one?

2. The important transformation

For arr = [1, 2, 3, 4, 5] the prefix sums are [0, 1, 3, 6, 10, 15]. Stand at the prefix 10 and think backwards. We want current − earlier = 6, so earlier = 4. There is no prefix 4, so no subarray ending here sums to 6. At the prefix 6 we need earlier = 0, and we have seen 0. That is [1, 2, 3].

Formally, sum(i … j) = prefix[j + 1] − prefix[i], and we want that to equal K. Rearranged:

prefix[i] = prefix[j + 1] − K. Instead of asking “which subarray sums to K?”, ask “have I seen a prefix equal to current_prefix − K?”

That is a much easier question, and it creates a new one: how do we quickly remember which prefix sums we’ve seen?

3. We need memory: a set for existence

Process the array left to right, computing the current prefix and asking whether current − K has been seen. A set answers “have I seen this value?”, which is all existence needs. Step through it, and try the second preset, where no subarray works.

Yellow is the current element, green the subarray found. The set holds every prefix seen so far.

Python code (click to hide or show)
def has_subarray_sum_k(nums, k):
    seen = {0}
    prefix = 0

    for num in nums:
        prefix += num

        if prefix - k in seen:
            return True

        seen.add(prefix)

    return False

Why does seen start as {0}? Because before any element, we have accumulated a sum of 0. This is the empty prefix, the same leading-zero idea from the last article. Without it we’d miss every subarray that starts at index 0.

A hashmap can do something more useful than a set: it can remember not only whether a value was seen but what information we attached to it. That matters shortly.

4. Equal prefix sums create zero-sum subarrays

If prefix[i] = prefix[j], then prefix[j] − prefix[i] = 0, so the elements between them sum to zero. For [1, -1, 1, -1] the prefix sums are 0, 1, 0, 1, 0.

Repeated prefix sums are not useless. A prefix sum isn’t merely a stored total: its relationship with another prefix sum tells us something about the subarray between them.

5. Subarray Sum Equals K: counting

Now ask: how many subarrays have sum K? A set isn’t enough, because with [1, -1, 1, -1] and K = 0 the same prefix appears several times and each occurrence is a different subarray. At every current prefix P we need an earlier prefix P − K, so instead of storing prefix → seen we store prefix → how many times we’ve seen it.

The naive way

Extend from every start, O(n²) subarrays.

Watch the counting

The third preset has prefix = [0, 1, 1, 3]. At the last step needed = 1 has appeared twice, so two different subarrays end here with sum 2. That is why the frequency hashmap is inevitable rather than magical.

Python code (click to hide or show)
def subarray_sum(nums, k):
    prefix_count = {0: 1}
    prefix = 0
    answer = 0

    for num in nums:
        prefix += num

        answer += prefix_count.get(prefix - k, 0)

        prefix_count[prefix] = prefix_count.get(prefix, 0) + 1

    return answer

Read the key line in English: how many times have I previously seen the prefix sum that would make my current prefix differ by exactly k? That number is exactly how many valid subarrays end here.

Why {0: 1}?

For nums = [2, 3], k = 2, at the first element prefix = 2 and we need 2 − 2 = 0. We haven’t processed anything, so where did that 0 come from? It is the empty prefix before the array starts. {0: 1} means “before processing any elements, prefix sum 0 has occurred once.” It is the same leading-zero idea again.

6. Negative numbers change the game

A tempting approach is: “if my sum gets too large, shrink the window.” That works in some sliding-window problems but not here. With negatives, adding an element can decrease the sum and removing one can increase it, so there is no monotonic relationship between window size and sum. Drag the window length and watch the sum go up and down.

Prefix sum + hashmap doesn’t care, because current_prefix − old_prefix = K is algebra and stays true whether numbers are positive, negative or zero.

Remember more so that we can compute less. And the memory is now much more powerful: it is used to discover hidden ranges.

7. Maximum Size Subarray Sum Equals K: the longest

Change the question again: what is the longest subarray whose sum is K? The equation is unchanged, old_prefix = current_prefix − K, but the hashmap must store something else. We no longer care how many times we saw a prefix. We care when we first saw it.

Why the first time? If the needed prefix occurred at index 2 and again at index 5, the subarray ending at j has length j − 2 or j − 5. The earlier occurrence gives the longer one. So the map becomes prefix → earliest index instead of prefix → frequency.

Here is the same array, [1, -1, 5, -2, 3] with K = 3, run in the longest mode. Then switch to the counting stepper above and notice that the equation never changed, only the stored value.

The map stores the earliest element index at which each prefix was reached. 0: -1 means the empty prefix, before index 0.

Python code (click to hide or show)
def max_subarray_len(nums, k):
    first_index = {0: -1}
    prefix = 0
    best = 0

    for i, num in enumerate(nums):
        prefix += num

        if prefix - k in first_index:
            best = max(best, i - first_index[prefix - k])

        if prefix not in first_index:
            first_index[prefix] = i

    return best

Note the last two lines: we only record a prefix the first time, because later occurrences would give shorter subarrays. This is a nice reminder to always ask: what information do I actually need to remember?

8. Contiguous Array: a disguised sum problem

Given a binary array like [0, 1, 0, 1, 1, 0], find the longest contiguous subarray with an equal number of 0s and 1s. We need a quantity that becomes zero when they are balanced, so transform 0 → −1 and 1 → +1. Now “equal zeros and ones” means sum = 0, and equal prefixes mean zero-sum subarrays. The problem has quietly become find the longest subarray with sum zero, which we already know how to solve. Step through it.

Python code (click to hide or show)
def find_max_length(nums):
    first_index = {0: -1}
    total = 0
    best = 0

    for i, x in enumerate(nums):
        total += 1 if x == 1 else -1

        if total in first_index:
            best = max(best, i - first_index[total])
        else:
            first_index[total] = i

    return best

9. The real power, and a mental template

The skill isn’t recognizing the words “prefix sum” in a problem statement. It is recognizing when a problem can be reduced to a difference between two accumulated states. sum = K becomes P[j] − P[i] = K, then P[i] = P[j] − K. “Equal zeros and ones” becomes a transformed sum of 0, then P[i] = P[j]. We keep converting a range condition into a relationship between two points in the prefix history.

The template has three steps. First, express the subarray as current prefix − previous prefix. Second, work out what the previous prefix must be (current − K). Third, decide what you need from the past.

This isn’t a collection of unrelated tricks. It is the same equation with different questions asked of the past.

Don’t memorize prefix_count = {0: 1} as a magic line. Understand it: I am walking through the array, remembering the states I’ve seen before, because a relationship between the current state and an earlier state tells me something about the subarray between them. Prefix sums are no longer just precomputed answers. They have become clues about the past.

In the next stage the question changes from “is the difference exactly K?” to “is the difference divisible by K?” The prefix-sum idea stays. Only the definition of a matching past state changes.

Two Pointers: Beyond the Basic Pattern

In the previous article, we built the intuition behind the two-pointer technique. The important thing was not to memorize “use two pointers when you see a sorted array.” Instead, we arrived at something more fundamental:

Two pointers are useful when two positions in a data structure can help us continuously eliminate parts of the search space.

Sometimes the pointers move toward each other. Sometimes they move in the same direction. Sometimes they define regions. Sometimes they move backward. And sometimes they don’t directly find the answer at all: they help us discover where the answer must be. That is what we will explore here, through four problems. 1. Dutch National Flag

Suppose an array contains only 0, 1 and 2, and we want to sort it. For example [2, 0, 2, 1, 1, 0] should become [0, 0, 1, 1, 2, 2]. At first glance this is a sorting problem, and arr.sort() is perfectly reasonable in Python. But the problem is interesting because we know something very specific about the data: there are only three possible values. So perhaps we don’t need a general-purpose sorting algorithm at all.

The naive way

We could count the values (0 → 2 times, 1 → 2 times, 2 → 2 times) and then rewrite the array. That works, with the idea “count first, reconstruct later.” Can we rearrange the array directly? This is where boundaries become useful.

Think in regions

The final order is known: 0s | 1s | 2s. Initially we don’t know where the regions end, but we can imagine growing them while we scan an unknown region. The regions are always:

all 0s
all 1s
unknown
all 2s
↑ low
↑ current
↑ high

That gives three pointers, and an invariant:

IndicesContents
[0 … low−1]all 0s
[low … current−1]all 1s
[current … high]unknown
[high+1 … end]all 2s

This invariant is the entire algorithm. The pointers are boundaries between regions whose correctness we already know.

What should happen with each value?

Look at the element at current. It is the first element of the unknown region, and it must join one of the known regions.

  • It’s a 0. It belongs at the end of the 0s. Swap it with arr[low] (the first cell of the 1s region). Both regions grew: low++, current++.
  • It’s a 1. It already belongs between the 0s and 2s. Nothing moves: current++.
  • It’s a 2. It belongs at the end. Swap it with arr[high] and high--. But current must not move.
The 0 case: swap with low
The 2 case: swap with high

Why must current stay in the 2 case? The element that arrived from high came from the unknown region. We haven’t examined it, and it might be a 0, a 1 or a 2 (in the figure above, it is a 0 that still needs to go left). One of the most important details of the algorithm. The complete algorithm

Python code (click to hide or show)
def dutch_national_flag(arr):
    low = 0
    current = 0
    high = len(arr) - 1

    while current <= high:
        if arr[current] == 0:
            arr[low], arr[current] = arr[current], arr[low]
            low += 1
            current += 1

        elif arr[current] == 1:
            current += 1

        else:  # arr[current] == 2
            arr[current], arr[high] = arr[high], arr[current]
            high -= 1

    return arr

The important part is not memorizing three cases. It is the invariant, and the question: how does the current element allow me to shrink the unknown region? Step through whole runs, including one with the bug of advancing current after a swap with high:

Why is this a two-pointer idea?

Technically we have three pointers, but conceptually this belongs to the same family. The important idea isn’t the number two. It is:

Use moving boundaries to maintain regions whose correctness is already known.

Why not just use sorting?

arr.sort() is much simpler, and in normal production code it may be the better choice. Here is the honest comparison:

Library sortCount, then rewriteDutch National Flag
TimeO(n log n)O(n), two passesO(n), one pass
Extra spacesmallO(1): three countersO(1)
Reasoning needednoneeasyan invariant with three regions
Works foranythinga few known valuesa few known values, one pass, in place

A theoretically better algorithm is not automatically the better piece of code.

Use the stronger algorithm when its constraints actually matter.

2. Quadruple Sum to Target

Now let’s increase the number of elements. We want all quadruplets whose sum equals a target. For [4, 1, 2, -1, 1, -3] and target 1, one answer is [-3, 1, 1, 2], because -3 + 1 + 1 + 2 = 1. At first this looks like a completely new problem. But we already know how to solve two-sum with two pointers on a sorted array. So instead of inventing a new technique, ask:

Can we reduce this problem to a problem we already understand?

This is one of the most useful habits in DSA.

Start with the brute force

A quadruplet has four elements, so the naive approach is four nested loops. That is a huge amount of work. But look at what happens if we fix two elements. If a + b + c + d = target and we choose a and b, then c + d = target − a − b. We have turned 4-sum into 2-sum.

When a problem asks for a combination of many elements, try fixing some of them and reducing the remaining problem to something you already know how to solve.

Why do two pointers work now?

Sorted, the array is [-3, -1, 1, 1, 2, 4]. Suppose we’ve fixed -3 and -1. The remaining target is 1 − (−3) − (−1) = 5. Place left on 1 and right on 4: 1 + 4 = 5, perfect. Had the pair summed to something too small, like 1 + 2 = 3, moving right left would only shrink the sum further, so the only useful move is left++. If it were too large, right--. Sortedness gives us directional information, exactly as before. Blue cells are the two fixed elements, yellow is the pair under inspection, grey is eliminated:

Implementation

Python code (click to hide or show)
def four_sum(arr, target):
    arr.sort()
    result = []
    n = len(arr)

    for i in range(n - 3):
        if i > 0 and arr[i] == arr[i - 1]:
            continue

        for j in range(i + 1, n - 2):
            if j > i + 1 and arr[j] == arr[j - 1]:
                continue

            left = j + 1
            right = n - 1

            while left < right:
                total = arr[i] + arr[j] + arr[left] + arr[right]

                if total == target:
                    result.append(
                        [arr[i], arr[j], arr[left], arr[right]]
                    )

                    left += 1
                    right -= 1

                    while left < right and arr[left] == arr[left - 1]:
                        left += 1

                    while left < right and arr[right] == arr[right + 1]:
                        right -= 1

                elif total < target:
                    left += 1

                else:
                    right -= 1

    return result

The code looks considerably more complicated than two-sum, but conceptually it isn’t a new technique. It is fix → fix → two pointers.

Why skip duplicates?

Suppose we have [-3, 1, 1, 1, 2]. If the first 1 and the next 1 play the same role, starting from both produces the same quadruplet. So after using a value, we skip equal values at the same decision level (try the third preset above, where every element is 2). This is another advantage of sorting: it didn’t just help the pointer movement, it made duplicates adjacent and easy to recognize.

Why not four nested loops?

Because most of that work is unnecessary. Once two elements are fixed we don’t test every remaining pair independently, since the sorted structure eliminates many possibilities at once. The progression is: check every quadruplet, then fix two and search the remaining two, then use sortedness to make that search two pointers.

The same idea for any k

Nothing special happened at 4. Fix k − 2 elements with nested loops, then finish with two pointers. Slide to see how the work compares at n = 100:

Optimization often comes from reducing a large search problem into a smaller familiar problem.

3. Comparing Strings Containing Backspaces

Now a very different-looking problem. Take s = "xy#z" and t = "xzz#". A # means delete the character immediately before it. So "xy#z" becomes "xz", and "xzz#" also becomes "xz". The strings are equal.

The obvious solution

Build each final string with a stack, then compare:

Python code (click to hide or show)
def process(s):
    stack = []

    for char in s:
        if char == "#":
            if stack:
                stack.pop()
        else:
            stack.append(char)

    return "".join(stack)

# process(s) == process(t)

This is simple and perfectly valid. But notice that the # affects the character before it. The string has a natural direction for reasoning: start from the end.

Why move backward?

Take a b # c. Scanning left to right, when we meet b we don’t yet know it will be deleted, so we must remember it. Scanning from the right, we meet the # before reaching b, keep a counter backspaces = 1, and when we reach b we know it’s deleted. We never store it. Compare what we must remember in each direction:

Two pointers

Put one pointer at the end of each string and move backward. Every # increases the number of pending deletions. Every normal character met while a deletion is pending is skipped. Eventually each pointer stops at the next character that actually survives, and we compare those. Grey cells are deleted (or are backspaces), green cells were compared and matched, yellow are the survivors being compared:

Python code (click to hide or show)
def backspace_compare(s, t):
    i = len(s) - 1
    j = len(t) - 1

    skip_s = 0
    skip_t = 0

    while i >= 0 or j >= 0:

        while i >= 0:
            if s[i] == "#":
                skip_s += 1
                i -= 1
            elif skip_s > 0:
                skip_s -= 1
                i -= 1
            else:
                break

        while j >= 0:
            if t[j] == "#":
                skip_t += 1
                j -= 1
            elif skip_t > 0:
                skip_t -= 1
                j -= 1
            else:
                break

        if i < 0 or j < 0:
            return i == j

        if s[i] != t[j]:
            return False

        i -= 1
        j -= 1

    return True

The important invariant

At every comparison, s[i] and t[j] are the next characters that would actually appear in the final strings. Characters that have been logically deleted are jumped over. This is a beautiful example of a broader idea:

Sometimes you don’t need to transform the data into its final form. You can reason about what the final form would be while traversing the original data.

Why not just use a stack?

The stack solution is arguably easier to understand. The backward-pointer solution uses O(1) extra space, while the stack needs space proportional to the input.

StackTwo pointers
Reasoningsimplermore complicated
Extra memoryO(n)O(1)
TimeO(n + m)O(n + m)

The lesson isn’t “two pointers are better.” It is: understand the trade-off and choose the technique according to the constraints.

4. Minimum Window Sort

Now a problem where the pointers don’t directly construct the answer. Take [1, 4, 6, 5, 2, 3, 7]. The array is almost sorted. We want the smallest subarray which, if sorted, makes the entire array sorted. Here that is [4, 6, 5, 2, 3]: sorting it gives [1, 2, 3, 4, 5, 6, 7].

The naive approach

Try every possible subarray, sort it, and check whether the whole array becomes sorted. That is a lot of unnecessary work. Instead ask: what does an unsorted array reveal about where the problem starts and ends?

Find where order first breaks

A sorted array satisfies arr[i] <= arr[i + 1]. Scan from the left for the first violation: here 6 > 5, so low = 2. Scan from the right for the last violation: scanning backward, 2 < 5 breaks the ordering, so high = 4. We have a candidate window [6, 5, 2]. But is it enough? Not necessarily.

Why might we need to expand the window?

The window’s minimum is 2 and its maximum is 6. Look at the element just outside on the left: 4 > 2. If we leave it outside, sorting only the window puts 2 after it and breaks the order. The element on the right, 3, is smaller than the maximum 6, so it would also end up out of order. Both must join the window. Switch between the two choices:

The deeper idea

The initial disorder tells us that somewhere between low and high something is wrong. But the values inside that region can affect elements just outside it. So we find the minimum and the maximum inside the window, then ask on each side:

  • Left: is the element just before the window greater than the window’s minimum? If yes, expand left, because after sorting the window that element would be out of order.
  • Right: is the element just after the window smaller than the window’s maximum? If yes, expand right, for the same reason.

We keep expanding until neither side needs to participate. Green cells are verified in place, yellow is the suspect window, blue cells were pulled in by an expansion:

Implementation

Python code (click to hide or show)
def minimum_window_sort(arr):
    n = len(arr)

    low = 0

    while low < n - 1 and arr[low] <= arr[low + 1]:
        low += 1

    if low == n - 1:
        return 0

    high = n - 1

    while high > 0 and arr[high] >= arr[high - 1]:
        high -= 1

    window_min = min(arr[low:high + 1])
    window_max = max(arr[low:high + 1])

    while low > 0 and arr[low - 1] > window_min:
        low -= 1

    while high < n - 1 and arr[high + 1] < window_max:
        high += 1

    return high - low + 1

The slicing in the min/max lines creates a temporary list in Python. If we care about strict constant auxiliary space, compute them with a loop instead, which keeps the reasoning closer to the theoretical in-place algorithm:

Python code (click to hide or show)
window_min = window_max = arr[low]

for i in range(low + 1, high + 1):
    window_min = min(window_min, arr[i])
    window_max = max(window_max, arr[i])

Is this really a two-pointer problem?

This one is worth thinking about carefully. It doesn’t look like the classic left → ← right pattern. The pointers first identify the boundaries of disorder and then expand them. So I would not treat “Minimum Window Sort = two pointers” as something to memorize. A better description:

Use two moving boundaries to identify the smallest region whose internal disorder affects the rest of the array.

The pointer technique is a consequence of that reasoning, and the distinction matters.

6. The bigger pattern

This is the real reason two pointers shouldn’t be learned as a collection of patterns. The name “two pointers” describes the implementation. It does not describe the underlying idea:

Can I represent a large search space using a small number of moving boundaries, and can I prove that everything outside those boundaries is already irrelevant?

That question leads to very different algorithms: left → ← right, or [correct] [unknown] [correct], or fix → fix → two pointers, or a single ← pointer, or [ unaffected | window | unaffected ]. The pointers are merely the mechanism. The real algorithm is the reasoning that makes pointer movement safe.

7. A useful way to recognize these problems

Instead of asking “is this a two-pointer problem?”, ask a better set of questions:

  1. Is there some structure in the data? Sorted order, known categories, logical deletions, nearly sorted structure.
  2. Can two positions tell me something about an entire region? “Everything before this pointer is already correct, everything after that pointer is already correct.”
  3. Can I permanently eliminate part of the search space? This is the most important question. If yes, ask why can I safely throw that part away? That “why” is usually the heart of the algorithm.
  4. What invariant am I maintaining? “Everything before low is 0 and everything after high is 2.” Or “arr[:write] contains unique values.” Or “the current pointers point to the next surviving characters.” The invariant tells us what the pointers actually mean.

8. The evolution of the idea

Across these problems, the idea has gradually expanded:

ProblemWhat the pointers do
Pair SumUse two ends to eliminate impossible pairs
Remove DuplicatesUse read/write positions to separate useful data
Dutch National FlagUse pointers as region boundaries
Quadruple SumReduce a larger problem until two pointers become applicable
Backspace CompareChoose pointer direction based on the problem’s meaning
Minimum Window SortUse boundaries to identify the smallest relevant region

That is why learning algorithms through intuition is more useful than memorizing patterns. The goal isn’t to look at left and right and immediately say “Two pointers!” The goal is to look at a problem and notice:

There is a lot of work here that I don’t actually need to do.

Then ask “what structure lets me prove that?” That is where the algorithm comes from.

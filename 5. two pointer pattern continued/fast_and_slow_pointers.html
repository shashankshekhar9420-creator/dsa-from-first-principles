Fast and Slow Pointers

So far, we have used two pointers in a few different ways. Sometimes they started at opposite ends:

L →                  ← R

Sometimes they both moved forward, but for different purposes:

slow →
fast →

The important lesson from two pointers was not: “Use two variables called left and right.” It was:

Keep track of two positions when the relationship between those positions gives you information.

Fast and slow pointers are simply another application of that idea. Here, the relationship is not usually where the pointers are. It is: how far each pointer has travelled.

One pointer moves slowly. The other moves quickly. And surprisingly, that difference in speed can reveal structural properties that would otherwise require extra memory or repeated traversal.

1. The Core Intuition: Relative Speed as an Information Probe

The Basic Idea & Linear Traversal

Imagine an ordinary linear linked list:

1 → 2 → 3 → 4 → 5 → 6 → None

Suppose we advance two pointers from the head, but with different step sizes:

Python code (click to hide or show)
slow = head
fast = head

while fast and fast.next:
    slow = slow.next
    fast = fast.next.next

Their trajectories unfold side-by-side:

slow: 1 → 2 → 3 → 4 → 5 → 6

fast: 1 → 3 → 5 → None

The two pointers travel through the exact same structure, but at different rates. If the structure is finite and linear, fast simply reaches None twice as fast as slow. But what happens if the structure contains a cycle?

What Happens in a Cycle: The Circular Track

Consider a list where node 6 connects back to node 3:

Once both pointers enter the cycle, neither pointer can escape. slow moves 1 step per turn (→ → → →), while fast moves 2 steps per turn (→→ →→). This is identical to two runners on a circular running track:

If one runner runs twice as fast as another on a closed loop, the faster runner must eventually lap and catch the slower runner.

Mathematical Derivation: Why Fast Must Catch Slow

Why can't fast jump cleanly over slow and skip it forever? The answer lies in relative distance:

Let the cycle contain L nodes.
In each iteration, slow advances +1 step.
In each iteration, fast advances +2 steps.
Relative speed: 2 - 1 = +1 node / iteration.
If the distance behind slow is d, then after 1 turn the distance is d - 1.
After 2 turns: d - 2 ... until d = 0 (Collision!).

Because the gap decreases by strictly 1 unit at each iteration, it is mathematically impossible for the gap to transition from 1 to negative without landing squarely on 0. They cannot skip past each other!

2. Problem 1: Linked List Cycle Detection

The Problem Statement

Given the head of a linked list, determine whether the linked list contains a cycle. For example:

1 → 2 → 3 → 4 → 5 → 3 ... (Cycle detected: return True)

Whereas 1 → 2 → 3 → 4 → 5 → None terminates (return False).

Set of Visited Nodes vs Movement

The naive approach uses a hash set to record every visited node:

Python code (click to hide or show)
def has_cycle_set(head):
    seen = set()
    current = head
    while current:
        if current in seen:
            return True
        seen.add(current)
        current = current.next
    return False

The reasoning is intuitive: “If I ever see the same node reference twice, I must have traversed a cycle.” However, if the list contains n nodes, the set consumes O(n) auxiliary memory. Can we detect the cycle with zero extra memory?

Floyd's Cycle Finding Algorithm

Instead of remembering every visited node in memory, we maintain two moving pointers: slow and fast. If fast encounters None, the list is acyclic. If slow is fast at any point, a cycle exists.

Python code (click to hide or show)
def has_cycle(head):
    slow = head
    fast = head

    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next

        if slow is fast:
            return True

    return False

Notice we use slow is fast (reference identity), not slow == fast. We verify whether they point to the exact same memory address, not whether two separate nodes happen to hold equal values.

Complexity & Boundary Safety

ApproachTime ComplexitySpace Complexity
Hash Set of visited nodesO(n)O(n)
Floyd's Fast & Slow PointersO(n)O(1)

The while condition while fast and fast.next: guarantees that we never access .next on a None object, terminating cleanly in acyclic lists.

Sometimes we can replace stored history with carefully designed movement.

3. Problem 2: Finding the Start of the Cycle

Why the Meeting Point Is Not the Entrance

Knowing that a cycle exists is useful, but many real-world problems require finding the exact entrance node where the cycle begins:

1 → 2 → 3 → 4 → 5 → 6 → 3  (Cycle entrance is node 3)

Notice that in Problem 1, slow and fast collided at node 5. The meeting point is almost never the entrance! Why should this collision help us locate the entrance? It doesn't directly — until we analyze the distance geometry.

Thinking in Distances: Defining a, b, and c

Let's partition the linked list into three precise distances:

  • a: Distance from head to the cycle entrance.
  • b: Distance from the cycle entrance to the meeting point.
  • c: Remaining distance from the meeting point back to the cycle entrance.

The total length of the cycle is L = b + c.

Interactive Derivation: Visualizing a ≡ c (mod L)

Let's derive the algebraic relationship step-by-step:

1. When slow and fast meet:
Distance travelled by slow: D_slow = a + b
Distance travelled by fast: D_fast = 2 × D_slow = 2(a + b)

2. Fast has also looped around the cycle k times (where k ≥ 1):
D_fast = a + b + k × L

3. Equating both expressions for D_fast:
2(a + b) = a + b + k × L
a + b = k × L

4. Express L as (b + c):
a + b = (k - 1)L + b + c

5. Subtract b from both sides:
a = (k - 1)L + c

This is the fundamental formula of Floyd's Cycle Detection. For k = 1 (the most common case where fast laps slow once), this simplifies directly to: a = c!

The distance from the head to the cycle start (a) is identical to the distance from the meeting point back to the cycle start (c)!

Derive it interactively: see why a = c aligns the dual race

Adjust the parameters below. Watch how moving one pointer a steps from head and another pointer c steps from the meeting point brings both pointers to the entrance at the exact same moment:

The Second Phase: Aligning the Dual Race

The algebraic equivalence a = c gives us an elegant two-phase algorithm:

  1. Phase 1: Run slow (1 step) and fast (2 steps) until they collide inside the cycle.
  2. Phase 2: Leave fast at the meeting point. Reset slow back to head. Now advance both one step at a time.
  3. Because both pointers must travel identical distances (a = c), they will collide at the cycle entrance!

Full Implementation & Verification

Python code (click to hide or show)
def detect_cycle(head):
    slow = head
    fast = head

    # Phase 1: detect meeting point
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            break
    else:
        return None  # No cycle exists

    # Phase 2: find cycle entrance
    slow = head
    while slow is not fast:
        slow = slow.next
        fast = fast.next

    return slow

4. Generalizing to State Machines: Problem 3 — Happy Number

The Happy Number Problem

Take any positive integer. Replace the number by the sum of the squares of its digits, and repeat:

19 → 1² + 9² = 82 → 8² + 2² = 68 → 6² + 8² = 100 → 1² + 0² + 0² = 1 (Happy!)

If the sequence reaches 1, the number is happy. But what happens if we start with 2?

2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 ...

The computation loops endlessly in an 8-number cycle: 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4.

The Hidden Linked List: Computed Next Pointers

Notice that every number has exactly one deterministic next number: next_state = sum_of_squared_digits(n). We don't need actual Node objects in memory. The computational function f(n) acts as the node.next reference!

Python code (click to hide or show)
def next_number(n):
    total = 0
    while n:
        digit = n % 10
        total += digit * digit
        n //= 10
    return total

def is_happy(n):
    slow = n
    fast = n

    while True:
        slow = next_number(slow)
        fast = next_number(next_number(fast))
        if slow == fast:
            break

    return slow == 1

5. Array as an Implicit Graph: Problem 4 — Find the Duplicate Number

The Problem and Special Constraints

Given an array of integers nums containing n + 1 integers where each integer is in the range [1, n] inclusive. There is only one repeated number. Find the duplicate without modifying the array and using only O(1) extra space.

nums = [1, 3, 4, 2, 2]   (n = 4, length = 5, duplicate = 2)

Mapping Indices to Values (i → nums[i])

Because every value in nums is between 1 and n, each value can be interpreted as a valid index in the array! If we define: current_node = i and next_node = nums[i], the array transforms into a directed graph:

Index 0 → nums[0]=1 → nums[1]=3 → nums[3]=2 → nums[2]=4 → nums[4]=2 → nums[2]=4 ...

Pigeonhole Principle: Why Duplicates Guarantee a Cycle

The array has n + 1 indices pointing to only n distinct target values. By the Pigeonhole Principle, at least two separate indices must contain the same value. That means two directed arrows merge into the same node! Once two paths merge, they enter a cycle. The entrance to that cycle is the duplicate value.

6. Beyond Cycles: Problem 5 — Middle of the Linked List

Single-Pass Midpoint Discovery

Suppose: 1 → 2 → 3 → 4 → 5. We want node 3 without counting the total length first. The standard two-pass approach traverses once to count n, then traverses n/2 steps in a second pass. Fast and slow pointers find the middle in exactly one pass.

The 2:1 Invariant: Halfway Across the Structure

Speed of fast = 2 × Speed of slow.
Distance of fast = 2 × Distance of slow.
When fast reaches the end (Distance = n), slow must have travelled n / 2 steps!
Python code (click to hide or show)
def middle_node(head):
    slow = head
    fast = head

    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next

    return slow

Interactive Midpoint Explorer: Odd vs Even Lengths

For odd lists, fast lands on the last node (fast.next is None). For even lists, fast reaches None, returning the second middle node (node 4).

A Foundational Primitive: Splitting the List

Finding the midpoint in O(n) time and O(1) space is a cornerstone primitive in DSA. It allows splitting a singly linked list into two equal halves without auxiliary arrays, serving as the basis for merge sort, palindrome checking, and list reordering.

7. Algorithmic Decomposition: Problem 6 — Palindrome Linked List

Why Singly Linked Lists Cannot Traverse Backward

In an array [1, 2, 3, 2, 1], we can place two pointers at the ends (L →   ← R) and compare inward. But in a singly linked list, there are no backward pointers!

The 3-Step Pipeline: Find Middle → Reverse → Compare

We decompose the problem into three reusable building blocks:

  1. Find the middle: Use fast/slow pointers to find the midpoint in one pass.
  2. Reverse the second half: Invert the next pointers of the second half in place.
  3. Compare halves: Move first from head and second from the reversed tail. If all values match, it is a palindrome!
Python code (click to hide or show)
def is_palindrome(head):
    slow = head
    fast = head

    # 1. Find middle
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next

    # 2. Reverse second half
    prev = None
    curr = slow
    while curr:
        nxt = curr.next
        curr.next = prev
        prev = curr
        curr = nxt

    # 3. Compare halves
    first = head
    second = prev
    while second:
        if first.val != second.val:
            return False
        first = first.next
        second = second.next

    return True

In-Place Mutation and Production Restoration

Operating in O(1) space temporarily mutates the list's second half. In production environments, it is good practice to run the reverse function on the second half once more before returning to restore the list to its original state.

8. Problem 7: Rearrange / Reorder a Linked List

The Problem: Alternating First and Last Nodes

Given 1 → 2 → 3 → 4 → 5 → 6, reorder the list into: 1 → 6 → 2 → 5 → 3 → 4 (first, last, second, second-last...).

Why Naive Traversal Becomes O(n²)

Because singly linked lists cannot jump to the tail, finding the last node repeatedly costs O(n) work per node, totaling O(n2).

Interactive 3-Phase Weaving Pipeline

We decompose the task into three linear-time operations:

  1. Find middle: 1 → 2 → 3 and 4 → 5 → 6
  2. Reverse second half: 6 → 5 → 4
  3. Weave nodes alternately: 1 → 6 → 2 → 5 → 3 → 4

Complete Implementation

Python code (click to hide or show)
def reorder_list(head):
    if not head or not head.next:
        return

    # 1. Find middle
    slow = head
    fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next

    # 2. Reverse second half
    prev = None
    curr = slow.next
    slow.next = None
    while curr:
        nxt = curr.next
        curr.next = prev
        prev = curr
        curr = nxt

    # 3. Weave alternate links
    first = head
    second = prev
    while second:
        tmp1 = first.next
        tmp2 = second.next
        first.next = second
        second.next = tmp1
        first = tmp1
        second = tmp2

9. Problem 8: Cycle in a Circular Array

Array Traversal with Modulo Arithmetic

Suppose nums = [2, -1, 1, 2, 2]. Each value indicates jump distance (positive = forward, negative = backward). The array wraps around circularly: next_index = (i + nums[i]) % n.

Constraints: Direction Consistency & Self-Loop Rejection

Unlike normal cycle finding, a valid loop must fulfill two critical criteria:

  • Single Direction: The cycle must move exclusively forward or exclusively backward (no direction flips).
  • Cycle Length > 1: Single-element self-loops (nums[i] % n == 0) do not count.

Interactive Circular Array Stepper

Full Implementation

Python code (click to hide or show)
def circular_array_loop(nums):
    n = len(nums)

    def next_index(i, direction):
        if nums[i] * direction <= 0:
            return -1  # Direction mismatch
        nxt = (i + nums[i]) % n
        return -1 if nxt == i else nxt  # Reject self-loops

    for i in range(n):
        direction = 1 if nums[i] > 0 else -1
        slow = i
        fast = i

        while True:
            slow = next_index(slow, direction)
            if slow == -1: break
            fast = next_index(fast, direction)
            if fast == -1: break
            fast = next_index(fast, direction)
            if fast == -1: break
            if slow == fast:
                return True

    return False

Fast/Slow vs Ordinary Two Pointers

Two pointers: Two positions whose values help us make decisions (e.g. sum too large → decrement right).

Fast/slow: Two positions whose speed ratio reveals hidden structural properties (e.g. cycle existence, midpoint).

The 5-Step Mental Framework for New Problems

Final Picture

Fast and slow pointers are not really about pointers. They are about using controlled motion to extract information from a structure.

Sometimes the smartest thing you can do is let one pointer walk while another runs. And sometimes, the distance between them tells you everything you need to know.

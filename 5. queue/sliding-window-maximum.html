Sliding Window Maximum: Why the Old Toolkit Breaks

We have spent the last few articles learning how sliding windows work. The central idea was: when a window moves, do not throw away everything you already know, update only what changed. We learned to maintain sums, counts, frequency maps, the number of distinct elements, the number of zeroes and character frequencies.

But there is one kind of information that is a little different. What if the question is: what is the maximum element inside the current window? That sounds simple, but it exposes an important limitation in the way we have been maintaining window state. Let us discover it.

1. The problem

Given nums = [2, 1, 5, 3, 4, 6] and k = 3, consider every contiguous window of size 3 and return the maximum of each. The windows are [2,1,5], [1,5,3], [5,3,4] and [3,4,6], with maxima 5, 5, 5, 6. The result is [5, 5, 5, 6].

At first glance this looks like a standard sliding-window problem. The window size is fixed, one element leaves, one enters. So let us start with what we already know.

2. Attempt one: just find the maximum

The naive way

For the first window [2, 1, 5] we scan it and find 5. Move the window to [1, 5, 3] and scan again. Then [5, 3, 4], scan again. This works, and there is nothing incorrect about it. But something feels wrong. Watch how much looking we do. Yellow is the element being examined.

3. We are repeating work

Look at two consecutive windows, [2, 1, 5] and [1, 5, 3]. Two of the three elements are identical, yet we scan all three again. We already knew 5 was the maximum of the previous window. Why are we examining it from scratch? Only two things changed: 2 left and 3 entered. Drag k to see how much is shared.

This is exactly the waste sliding window was designed to eliminate, so ideally our work should focus on what changed.

4. What we want from our window state

For a sum problem we can do old sum - leaving element + entering element. For [2, 1, 5] the sum is 8, and moving to [1, 5, 3] we say 8 - 2 + 3 = 9. The old state is updated from the new information. Can we do something similar for the maximum? Try it:

Maximum is not additive. And there is a deeper problem.

5. What if the maximum leaves?

Consider [5, 3, 4] with maximum 5. The window moves to [3, 4, 2]. The 5 has left, so our old maximum has disappeared. We need to know that 4 is the new maximum, but if all we remembered was maximum = 5, we have lost the information we need. Switch between the two strategies:

For a sum, losing one element is easy to repair. For a maximum, losing the current maximum can reveal an older candidate that we previously ignored. So perhaps we need to remember more than just the current maximum.

6. Too little, too much, just right

A reasonable next attempt: keep the entire window. When 5 leaves we can find the new maximum from [3, 4]. But we are back to scanning, which defeats the purpose. We want something between two extremes.

Keep only the information that might matter later.

7. Which elements could matter later? Domination

In [5, 3, 4] the maximum is 5, but we should not forget 3 and 4, because 5 may leave. If it does, 4 becomes the maximum, so 4 is a useful candidate. What about 3? Once 4 is present after it, ask: can 3 ever become the maximum while 4 is still inside the window? No. 4 is larger, and 4 is newer.

Think about lifetimes. Because 3 is older, it leaves the window before 4. So while 4 is around, 3 < 4; and after 4 leaves, 3 has already left too. This is stronger than "4 is currently bigger". We can say 4 completely dominates 3. An older element 3 sits in the window and a newer element arrives. Drag its value:

A newer, larger element dominates an older, smaller one. The older one can never be the maximum again, so we can safely forget it.

8. A new element arrives

Take window [5, 3, 2]. The best candidate is 5, but we should not throw away 3 and 2, because if 5 leaves, 3 becomes the maximum. All three are potential candidates, and notice they are already decreasing: 5 > 3 > 2. The best candidate is at the front, the weaker ones behind it.

Now 4 enters. Ask of each candidate from the back: can it become the maximum while 4 is inside? Step through, and try the other presets.

Notice what just happened

When 4 arrived we did not ask "what is the maximum of the entire window?". We asked a much smaller question: which candidates has this new element made useless? Instead of recomputing the answer we continuously eliminate things that can no longer contribute to it.

Do not redo work that has already been settled. Now applied to the ordering of candidates.

9. Why we need both ends

Now the reason for learning the deque becomes clear. With candidates [5, 3, 2], the largest candidate is at the front, so the current maximum is whatever is at the front. But when a new element 4 arrives, we remove dominated candidates from the back: 2 < 4 so remove, 3 < 4 so remove, giving [5], then add 4 to get [5, 4].

The two ends have different jobs, and that is why the deque is so useful.

10. Expiration and the four rules

We have solved one problem: removing dominated candidates. But sliding windows have another rule: elements eventually leave the window. In [5, 4, 2] the maximum 5 is at the front, but eventually the left side moves past it. We cannot keep using it as the answer, so we must remove expired elements too. Where is the candidate that would expire first? At the front. So we have two reasons to remove an element:

EndReasonMeaning
Frontexpiredremoved because it left the window
Backdominatedremoved because it can never become the answer

We are not randomly deleting elements. Each deletion has a reason.

For every new element, the structure is beginning to emerge as four rules. Pick one:

Python code sketch (click to hide or show)
# Only a sketch of the four rules. The next article turns this
# into the complete algorithm and analyses why it is efficient.
for i, x in enumerate(nums):
    while dq and dq[0] <= i - k:          # Rule 1: remove expired (front)
        dq.popleft()
    while dq and nums[dq[-1]] < x:        # Rule 2: remove dominated (back)
        dq.pop()
    dq.append(i)                           # Rule 3: add the new candidate
    if i >= k - 1:
        out.append(nums[dq[0]])            # Rule 4: the front is the maximum

11. Why is the front always the maximum?

Suppose we maintain candidates [9, 7, 5, 2]. They are decreasing, so the front, 9, is the maximum. Now 6 arrives. From the back: 2 < 6 remove, 5 < 6 remove, 7 > 6 stop. Add 6 and the sequence is still decreasing: [9, 7, 6]. Therefore the largest element is still at the front. Try several arrivals, including a tiny one that removes nothing and a huge one that removes everything.

The candidates stay in decreasing order, so the front is always the maximum. This property is what we call monotonic.

12. The candidate structure is not the window

We can now describe what our deque contains. It does not contain every element of the window. It contains only elements that could still become the maximum, kept in decreasing order. For the window [1, 5, 3, 4, 2] the candidate deque is [5, 4, 2]. Why is 1 not there? 5 dominates it. Why not 3? 4 arrived later and is larger. Drag to add elements one at a time:

The deque is a compressed representation of the information we actually care about: not the whole window, not just the current maximum, but the remaining possible maxima.

14. What these problems taught us

The important shift in thinking is a sequence of ideas, each one fixing the last. The data structure is not the starting point. The reasoning is, and the deque comes after the reasoning. Walk through it:

The most important sentence from this entire problem is not "use a monotonic deque". It is the one in the quote at the top of this post.

15. The bigger pattern: still sliding window

It is important not to think of this as an entirely new pattern. The sliding window is still doing what it always did: right explores, left removes expired elements. What is new is the state we maintain inside the window. Previously it might have been a sum, a frequency map, a distinct count or a zero count. Now it is ordered candidates for the maximum.

Sliding window plus specialized state. The monotonic deque is simply a clever way to maintain that particular state.

16. A useful way to recognize these problems

  1. Is the window contiguous and moving? Then a sliding window may apply.
  2. Is the answer a sum or count that updates additively? A running value is enough.
  3. Can the leaving element change the answer unpredictably? A maximum or minimum can, because losing it reveals an older candidate.
  4. Which elements could still matter later? Ask what a newer, better element makes permanently useless.
  5. Where do removals happen? Expired elements leave from one end, dominated ones from the other. That points to a deque.
  6. Is the structure ordered? If the candidates must stay in decreasing order, the front is the answer.

17. The evolution of the idea

ApproachProblem
Scan every windowRepeated work on overlapping elements.
Remember only the maximumThe maximum may leave, and we need to know who comes next.
Remember everythingWe would have to search through everything again.
Keep only useful candidatesInsight: a newer, larger element makes smaller older elements permanently irrelevant.
Order candidates in decreasing orderNow the front is the largest candidate.
Remove from the back when dominated, from the front when expiredThe structure stays correct and synchronized with the window.

That gives us the monotonic deque. For Sliding Window Maximum, a newer element that is larger than an older element dominates it, and once dominated, the older element can never be the maximum again, so we discard it. The remaining candidates are kept in decreasing order, so deque[0] is the maximum.

Monotonic Deque: Keeping Only What Can Still Win

In the previous article we reached an important realization. The problem with Sliding Window Maximum was not that we did not know how to find a maximum. The problem was that the window keeps moving. When the current maximum leaves, we need to know who is the next element that could possibly become the maximum. Remembering everything makes us scan again, and remembering only the current maximum leaves us stuck when it expires.

So we arrived at the idea of candidates: instead of remembering every element, keep only the elements that can still matter. Now we can finally give that idea a name.

Monotonic Deque: keep only the candidates that can still win, best one at the front.

1. The problem

Given an array and a window size k, find the maximum value in every window. For nums = [2, 1, 5, 3, 4, 6] and k = 3 the windows have maxima 5, 5, 5, 6, so the answer is [5, 5, 5, 6].

The windows overlap heavily: only one element enters and one leaves as the window moves. The question is how to use that overlap instead of repeatedly scanning it.

2. First, remember what a candidate is

Suppose the window is [5, 3, 2] and 4 enters. Can 2 ever become the maximum again? No. 4 is newer and larger, and because 4 entered later, 2 will leave the window before 4 does. While 4 is alive, 2 can never win. The same is true for 3. So after adding 4 we do not need 5, 3, 2, 4. We only need 5, 4. These are the candidates: the elements that could still become the maximum at some future point.

3. The deque gives us exactly what we need

We need two things. The best candidate should be easy to access, so we keep the strongest candidate at the front. And when a new, larger value arrives, weaker candidates are removed from the back. A deque gives us exactly these operations.

Look at the best candidate from one end, while eliminating useless candidates from the other.

We did not pick the deque because "Sliding Window Maximum uses a deque". We arrived at it because the problem requires working at both ends.

4. Why we store indices, not just values

This is an important detail. We do not store [5, 4, 3]; we store their indices. For nums = [2, 1, 5, 3, 4, 6] a deque of [2, 4] means the values [5, 4]. Why bother? Because values tell us how large something is, and indices tell us whether it is still inside the window.

Take nums = [5, 3, 4] and k = 2. The window moves from [5, 3] to [3, 4], and the 5 is no longer inside. Compare what each design knows:

Values help us decide who is stronger. Indices help us decide who is still alive.

5. What does "monotonic" mean?

For a maximum problem, the values in our deque decrease from front to back, for example [5, 4, 2, 1], and the largest is always at the front. That is all "monotonic" means here. It does not mean the original array is sorted; it can be completely unsorted, like [2, 1, 5, 3, 4, 6]. Only the candidates inside the deque are kept in monotonic order. 6. The two reasons an element can leave

An element can leave our deque for exactly two conceptual reasons.

Front: expiration. Back: domination. That is the heart of the algorithm.

7. The invariant

At every point, our deque maintains four properties. In the walkthrough below, the checks are evaluated for real after each element is processed, so you can watch them hold.

For each entering element choose the next move. Rule 1 comes first (expired front), then Rule 2 (dominated back), then append. Note that an equal back value counts as dominated here, which we explain in section 11.

9. The algorithm

Now that the reasoning is clear, the code becomes surprisingly small.

Python code (click to hide or show)
from collections import deque


def max_sliding_window(nums, k):
    dq = deque()
    result = []

    for right, value in enumerate(nums):

        # Remove indices that have left the window.
        while dq and dq[0] <= right - k:
            dq.popleft()

        # Remove candidates that can never beat the new value.
        while dq and nums[dq[-1]] <= value:
            dq.pop()

        dq.append(right)

        # The window is complete.
        if right >= k - 1:
            result.append(nums[dq[0]])

    return result

There is no magic hiding in it. Every line corresponds to one piece of reasoning we already discovered: expired means remove from the front, dominated means remove from the back, a new candidate is appended, and when the window is ready the front is the answer. 10. Why remove expired elements first?

Suppose the front contains an element that has already left the window. We must not treat it as the maximum, so before using the front as the answer we make sure it is a currently alive candidate. The ordering is naturally: remove dead candidates, remove dominated candidates, add the new candidate, read the best candidate. 11. What about equal values?

We used nums[dq[-1]] <= value rather than <. Why? Consider [5, 5]. The newer 5 is at least as good as the older one, and it stays in the window longer, so the older 5 is dominated and can safely go. Using < would keep equal values too. That also works, but it stores more candidates than necessary. Compare the two on a run of equal values:

For a maximum, a newer value that is greater than or equal to an older value makes the older candidate unnecessary.

12. Why is this actually O(n)?

At first glance the code has a while inside a loop, which might look like we repeatedly scan many elements. But notice that an element can be appended once, removed from the back at most once, and removed from the front at most once. Once removed, it never comes back: append, remove, gone forever. Across the whole array the number of deque operations is proportional to the number of elements. Count the real operations on several arrays:

The time is O(n) with O(k) space in the worst case. The intuition is not "while loops somehow become O(n)". It is that every element enters once and can leave only once.

There is no endless rework.

14. The deeper idea: compressing information

This is perhaps the most important lesson. The window might contain [2, 1, 5, 3, 4], but we do not need all of it. After processing, we might only need [5, 4]. We have compressed the window into the information that can still affect the future answer.

When a problem keeps moving through overlapping data, ask whether some pieces of information can be permanently discarded.

15. Why does the deque stay ordered?

Imagine the deque contains [8, 6, 3] and 7 arrives. From the back: 3 < 7 remove, 6 < 7 remove, 8 > 7 stop. Then [8, 7] is still decreasing. Why remove from the back rather than somewhere in the middle? Because the new element can only dominate candidates that are weaker than it, and those are precisely at the back. The monotonic ordering makes them easy to eliminate, and that ordering is what turns the deque into a useful structure rather than a generic double-ended queue.

16. The minimum version

The exact same reasoning works for the minimum of every window. We simply reverse the dominance relationship.

Python code (click to hide or show)
# Maximum: the deque is decreasing, the front is the largest
while dq and nums[dq[-1]] <= value:
    dq.pop()

# Minimum: the deque is increasing, the front is the smallest
while dq and nums[dq[-1]] >= value:
    dq.pop()

Remove candidates that can no longer win.

The entire sliding-window idea compresses into four sentences: right explores, left repairs, state remembers, the constraint decides. And when the answer itself needs ordered candidates: the deque remembers only who can still win.

The window decides who is alive. The deque decides who is still capable of winning.

We did not really learn a "deque trick". We learned a way of thinking about data. When information becomes permanently irrelevant, delete it. When several pieces of information remain possible, organize them so the most useful one is easy to access. When the problem moves forward, do not recompute everything from scratch; maintain the useful state.

19. A useful way to recognize these problems

The pattern is no longer "I see a sliding-window problem, so I use technique X". Ask these questions instead.

  1. What changes when the window moves? One element leaves, one enters.
  2. What information do I need to preserve? A sum, counts, or the best candidates.
  3. What information has become useless? Something a newer, better element makes irrelevant.
  4. Can I discard it permanently? If a newer element dominates an older one forever, yes.
  5. Which end is each removal from? Expired from the front, dominated from the back.
  6. Do I need indices? If I must know whether a candidate is still alive, yes.
  7. Maximum or minimum? That decides whether the deque is decreasing or increasing.
